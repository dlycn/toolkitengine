# 元素创世 · 项目介绍

<center><a href="readme.md">返回主页</a></center>

本文档旨在系统性地阐述“元素创世”项目的设计哲学、理论框架与工程实现方案。本项目并非一款传统意义上的沙盒游戏，而是一个**基于非线性动力学、频谱分析与负反馈控制理论的持续演化的可观测宇宙模型**。其最终目标是构建一个在**计算资源有限的前提下，能够在感知层面呈现“无限”深度与连续性的程序化生成世界**。

---

## 一、核心设计哲学

1. **从“以太”到万物的涌现论**  
   世界并非由预设地图定义，而是从均匀且参数为1的“以太”基底开始，经由冰、火等基本元素反应，逐步涌现出泥土、岩石、水体与生命。创世不是一次性的生成，而是一个**持续进行的动态过程**。其数学本质是**从均匀稳态出发，通过对称性破缺逐步产生复杂结构的偏微分方程演化系统**。

2. **负反馈作为创世引擎与博弈擂台**  
   创世的力量并非单向的“创造”，而是通过负反馈机制抵抗外来干涉，并在扰动后恢复周期节律。这种抵抗与恢复的过程本身就是地形、气候与生态形成的内在驱动力。  
   同时，负反馈回路构成**玩家与天道博弈的擂台**：玩家每投入一份元素扰动，都是在测试世界节律的恢复极限。当扰动强度或持续时间突破该区块的“记忆时间常数”时，该区块的周期设定点将被永久改写——**这是玩家在“创世”上留下的签名**。

3. **可追溯的渐进式演化**  
   所有变化均基于确定性规则和初始种子，玩家行为作为外部事件被记录。世界可以从任意时间点重建或分叉，使创世过程具备时间维度的可逆性与可探索性。  
   这依赖于**确定性算法与固定时间步长**的耦合，确保“相同的输入序列永远产生完全相同的输出状态”。

4. **观测者中心主义与锚点赋予**  
   世界的连续性只围绕主角所在时空展开。远离观测者的区块进入抽象节律状态，仅在需要时通过周期因子与偏置时间重建。  
   这不意味着玩家是被动的观测者。当玩家选择在某处定居、战斗或改造时，该区块从“抽象的周期函数”变为“鲜活的历史现场”——**玩家的每一次决策都在为世界的频谱添加新的谐波分量**。世界因玩家的存在而从不完整走向完整。

5. **元素反应作为玩家与世界对话的语言**  
   创世过程不依赖脚本事件，而是让玩家通过放置冰、火等源，直接参与并扰动世界的物质转化。玩家的每一次交互都是对创世进程的一次干预，世界则通过负反馈进行回应，形成动态平衡。  
   玩家可以**主动选择**这条对话的深度：短暂放置是“试探”，持续经营是“契约”，大规模改造则是“战书”。当玩家证明自己有能力维持某个非平衡状态足够久时，该系统会将该状态**固化为新的周期参数**，从而形成真正属于玩家的“领地烙印”。

6. **玩家权能声明：有限操作，无限回响**  
   本项目坚持“有限递归世界”的闭合模型（详见第七节），其根本原因在于：  
   - 玩家可同时清晰操控的焦点对象不超过6～7个（符合工作记忆7±2组块规律）。  
   - 真正有意义的“控制力”不在于玩家能影响多少个坐标点，而在于其有限行动在无限频谱中留下的**可追溯谐波印记**。  
   - 因此，世界被设计为一个**数学上闭合（周长2²⁰单位）、感知上开放**的递归环面，在此范围内任何玩家的行动均可被记录、追溯与回响，而不会被坐标的无限扩张所稀释。

## 二、预计涉及的理论知识图谱

> **说明**：以下各条目均为支撑系统运行的必要理论组件，彼此通过“区块节律-观测窗”架构形成完整闭环，而非孤立工具。

1. **非线性动力学与极限环理论**  
   用于为每个区块设计稳定的周期振荡行为（以范德波尔振荡器为核心模型），确保区块在没有外部扰动时回到固定节律，有扰动时也能逐步恢复。  
   区块的“节律”本质上是其在相空间中的**稳定极限环**。该极限环的存在性与唯一性由系统的李雅普诺夫函数保证。

2. **偏微分方程数值方法**  
   热方程、反应-扩散方程、对流扩散方程等用于描述温度场、以太浓度场的连续演化。有限差分法、有限体积法作为离散化基础。  
   在观测窗内（5×5区块），这些方程以固定时间步长进行迭代求解；在观测窗外，其解被**谱截断**为若干主频分量，以周期边界条件形式存储。

3. **流体模拟与压力求解**  
   借鉴Stable Fluids方法，通过亥姆霍兹分解和泊松方程求解不可压缩速度场，实现元素反应引起的“空间挤压”和以太流动。  
   该模块直接与元素反应耦合：火焰加热导致密度下降，引发压力梯度驱动的流体平流，将热量与物质输送到相邻区块。

4. **控制理论与PID控制器**  
   区块内部的负反馈调节直接使用比例-积分-微分控制逻辑，使气候、物质状态等变量追踪动态周期设定点，抵抗外部干扰。  
   控制器参数（比例增益 \(K_p\)、积分时间 \(T_i\)、微分时间 \(T_d\)）决定区块的“韧性”和“恢复速度”，并作为4KB区块存档中的常驻参数。

5. **元胞自动机与反应扩散系统**  
   在离散原型阶段快速验证冰火反应、物质转化规则，并作为连续模型的简化补充。  
   用于低计算预算下的快速原型测试，不作为最终运行时架构的一部分。

6. **频谱分析与快速傅里叶变换（FFT）**  
   将区块的地形或生态状态从空间域变换到频域，只保留少数主要频率分量作为周期参数存储，实现**有损压缩与快速重建**。  
   压缩比通常达到 \(10^3\) 至 \(10^4\) 量级，是“周期折叠”机制的核心数学工具。

7. **分布式系统最终一致性**  
   区块独立演化，通过向量时钟、状态合并等机制保证区块间交互的一致性，使玩家穿越边界时无缝衔接。  
   区块间的耦合强度被设计为弱耦合（系数 \( \epsilon \ll 1 \)），以保证即使出现临时不一致，系统也能够在有限步内收敛。

8. **ECS架构与确定性模拟**  
   实体组件系统分离底层自然场与玩家上层修改，通过确定性算法和固定时间步长保证重放与多线程一致性。  
   System层负责场更新，Component层仅存储偏差值（delta），实现底层与上层的高度解耦。

9. **GPU并行计算与着色器编程**  
   使用计算着色器在GPU上并行求解偏微分方程和场更新，实现观测窗内的高性能实时仿真。  
   每个线程处理一个格点，共享内存用于局部邻域通信，显存占用被严格限制在观测窗范围内（约400万像素等效）。

10. **事件溯源与谱方法状态压缩**  
    世界状态存储采用“初始条件 + 事件日志 + 周期参数”混合模型，结合谱方法对自然生态进行高效表达，避免事件列表膨胀。  
    事件日志仅记录玩家触发的**上层偏差**，自然演化部分完全由确定性规则重放，无需存储。

## 三、周期性节律实现的具体方案

> **预处理特征 3.1 至 3.9 属于架构层面的刚性设计，任何偏离均需重新论证其数学稳定性。**

### 3.1 区块核心建模为非线性振荡器

每个5×5区块拥有一个或多个范德波尔振荡器，其状态变量可映射为区块的平均温度、以太浓度或生态活力。振荡器参数（固有频率、阻尼系数、耦合强度）由区块的初始条件和边界环境决定。

范德波尔方程的标准形式：
\[
\frac{d^2x}{dt^2} - \mu(1 - x^2)\frac{dx}{dt} + \omega^2 x = 0
\]

其中 \(\mu\) 控制非线性阻尼强度，\(\omega\) 为固有角频率。区块的宏观状态被编码为 \(x(t)\) 及其导数 \(\dot{x}(t)\) 在极限环上的相位角 \(\theta(t) = \arctan(\dot{x}/\omega x)\)。

### 3.2 周期参数存储格式

区块存档中只保存振荡器的关键参数：振幅 \(A\)、频率 \(\omega\)、相位偏置 \(\phi\)、阻尼系数 \(\mu\)，以及可能的多频率分量（类似傅里叶级数的前2～3项）。

存储数据结构（4KB对齐）：
```
struct BlockRhythm {
    float64 amplitude;        // 8 bytes
    float64 frequency;        // 8 bytes
    float64 phase_offset;     // 8 bytes
    float64 damping;          // 8 bytes
    float64 harmonics[3][2];  // 3 harmonics × (amp, phase) × 8 = 48 bytes
    uint64 last_update_tick;  // 8 bytes
    // 总计约 88 bytes，剩余空间用于场数据和偏差
};
```

### 3.3 观测窗内外切换机制

当玩家进入某区块影响范围时：
1. 系统根据当前全局时间 \(T\) 和区块的周期参数 \(\{\omega, \phi, A, \mu\}\)，解析计算出区块的完整场状态 \(S(T) = \mathcal{F}^{-1}(\omega, \phi, A, \mu)\)。
2. 将解析结果作为初始条件，启动该区块的实时仿真（PDE迭代）。

当玩家离开时：
1. 运行快速傅里叶变换（FFT）将当前场状态 \(S(t)\) 压缩回周期参数，更新相位偏置 \(\phi \leftarrow \phi + \omega \Delta t\)。
2. 停止实时仿真，释放GPU资源。

该切换的连续性是**解析解与数值解在边界处的 \(C^1\) 连续**所保证的。

### 3.4 负反馈调节回路

区块内部包含一个PID控制器，以振荡器的周期轨迹为设定点。玩家触发的元素反应引入扰动 \(e(t)\)，控制器输出修正力 \(u(t)\)：
\[
u(t) = K_p e(t) + K_i \int_0^t e(\tau) d\tau + K_d \frac{de}{dt}
\]

输出修正力用于调节物质转化速率、温度扩散系数等参数，驱动区块状态返回设定点。控制器参数决定区块的“韧性”和“恢复速度”，与区块的\(\mu\)系数存在单调映射关系。

### 3.5 区块间耦合与边界通量

相邻区块通过虚拟边界交换温度、湿度等通量。交换方程：
\[
\Phi_{i \to j} = \alpha \cdot (S_i - S_j) \cdot \mathbb{1}_{\|S_i - S_j\| > \delta}
\]

其中 \(\alpha\) 为耦合系数，\(\delta\) 为死区阈值，防止数值震荡。

在周期模式下，区块之间的耦合简化为对周期参数的小幅修正（摄动法）；在实时模式下，直接进行场值交换（直接Neumann边界条件）。

### 3.6 智能体行为的周期折叠

区块内的生物智能体拥有自己的内在节律。当区块进入周期模式时，智能体的集体行为被压缩为区块的附加周期参数（如种群密度波动频率）。

玩家返回时，根据这些参数重新展开具体智能体，并利用区块的负反馈机制使其与地形演化同步。展开算法采用**确定性哈希映射**（见第五节），确保每次展开得到相同结果。

### 3.7 恢复过程与偏差衰减

玩家破坏或放置造成的上层偏差被单独存储（作为Component层）。当区块处于周期模式时，偏差以由负反馈强度决定的速率向零衰减：
\[
\Delta(t) = \Delta_0 \cdot e^{-\lambda t}
\]

其中 \(\lambda\) 与PID控制器参数 \(K_p, K_i, K_d\) 直接相关。

恢复过程并非瞬时重置，而是逐渐逼近底层场，保留时空连续性。当 \(\Delta(t) < \epsilon\)（\(\epsilon\) 为量化阈值）时，偏差记录被清除，以节省存储空间。

### 3.8 性能与一致性保障

- 实时仿真仅发生在主角周围的5×5区块内。
- 每个区块的PDE迭代采用固定时间步长（\(\Delta t = 1/60\) 秒）。
- 通过计算着色器并行加速。
- 周期模式的更新成本几乎为零（仅需 \(O(1)\) 次浮点运算）。
- 一致性通过**确定性的全局时间戳**保证：所有区块共享同一个单调递增的全局时钟。

### 3.9 标记生物追踪的妥协方案：全局签名频率表

> 此为工程层面的关键修正。若无法实现，则“无限递归世界”的叙事承诺将无法兑现。

为解决“标记生物跨区块追踪”的IO爆炸问题，本项目采用**全局签名频率表**（Global Signature Frequency Table, GSFT），而非将生物实体分散存储于各区块存档中。

- **存储位置**：世界根目录下的独立文件，大小固定为 \(N_{\text{max}} \times 32\) 字节，其中 \(N_{\text{max}}\) 为系统支持的最大标记生物数量（建议 \(N_{\text{max}} = 65536\)，总大小约2MB）。
- **存储内容**（每条记录32字节）：
  - 生物签名：16字节哈希（SHA-1截断），用于唯一标识。
  - 所在区块坐标：8字节（I32索引对）。
  - 绑定的谐波分量索引：4字节，指向该区块周期参数中的某一条频率。
  - 状态标志：4字节（存活/休眠/已迁移）。
- **更新逻辑**：
  - 玩家收复生物 → 生成签名，写入GSFT，并将行为模式映射为所在区块的新增谐波分量。
  - 生物跨区块移动 → 仅更新GSFT中的“所在区块坐标”字段；在原区块中删除谐波分量，在新区块中添加（\(O(1)\) 操作，不涉及实体数据复制）。
  - 区块进入周期模式 → 该区块内的所有标记生物状态被折叠为谐波分量，GSFT中的生物记录保留，但“状态标志”设为“休眠”。
  - 玩家返回 → 根据区块周期参数 + 生物签名，反演展开该生物。
- **一致性保障**：GSFT的更新与区块状态更新在同一事务中进行（通过全局时间戳标记），确保不会出现“生物记录指向不存在的谐波”的悬挂引用。

该方案的核心优势在于：**无论玩家标记了多少生物，跨区块移动的操作代价恒定**（\(O(1)\) GSFT更新），且与区块总数无关。这使得在2²⁰环面世界内追踪任意数量的标记生物成为可行。

## 四、地图生成与区块结构

1. **元素驱动的初始状态**  
   世界初始化为平坦的“以太”场，参数统一为1，不存在预设地形。地形完全由冰与火等元素反应驱动物质转化而涌现。  
   初始条件为全空间常数 \(u_0(x, y) = 1\)，边界条件为周期性（环面拓扑）。

2. **区块自治与周期节律**  
   世界被划分为 \(5 \times 5\) 大小的区块（单位：格点，非视觉尺寸）。每个区块都拥有独立的动力学参数（如振幅、频率、相位），构成一个自持的周期振荡系统。  
   区块脱离玩家观测后进入离散的节律模式，仅存储周期常数因子和偏置时间，而非完整状态。  
   区块的划分粒度基于两个考量：(1) 5×5满足GPU线程块的最佳尺寸；(2) 视觉LOD裁剪以5×5为最小单位可减少拼接缝隙。

3. **观测窗连续仿真**  
   只有主角周围一定范围内的区块进入实时物理仿真模式（即前文所述的5×5观测窗），其余区块按周期函数进行暴力更新，实现性能与一致性的平衡。  
   观测窗的尺寸（5×5）基于经验测试：小于5×5会导致玩家快速移动时出现加载空洞，大于5×5则会超出移动端GPU的实时计算预算（参见第七节性能边界）。

4. **边界无缝衔接**  
   区块间通过弱耦合边界通量（能量、物质缓慢渗透）保持逻辑一致，玩家穿越区块时不会察觉状态跳变。  
   耦合强度 \(\alpha = 0.01\) 经实验确定为视觉平滑与计算稳定性的最佳折中点。

## 五、智能体行为与生态动力

1. **非马尔可夫更新**  
   智能体行为不仅取决于当前状态，还受内部振荡器与历史记忆影响，避免陷入简单反应模式，产生更自然的节律行为。  
   每个智能体拥有一个内部相位变量 \(\phi_{\text{agent}}\)，与所在区块的振荡器相位 \(\phi_{\text{block}}\) 耦合：  
   \[
   \frac{d\phi_{\text{agent}}}{dt} = \omega_{\text{agent}} + \gamma \sin(\phi_{\text{block}} - \phi_{\text{agent}})
   \]  
   其中 \(\gamma\) 为耦合强度。

2. **与区块节律同构**  
   智能体的内在周期与所在区块的地形节律耦合。当玩家离开区块时，智能体行为被折叠进区块的周期函数参数中；玩家返回时再展开为具体实体，保持生态一致性。  
   展开算法详见**预处理特征3.6**。

3. **负反馈驱动的生命感**  
   智能体与环境间的相互作用被设计为负反馈环，使得生态在受到玩家干扰后能逐步回归稳定周期，展现“世界生命力”。  
   具体表现为：种群密度偏差 \(D_{\text{pop}}\) 通过PID控制器调节繁衍速率，使密度跟踪由区块振荡器确定的动态设定点。

4. **谱分解替代事件日志**  
   对于自然尺度的生态演化，不记录“何时发生何事”，而是用傅里叶级数或类似谱方法将生态动态压缩为少数频率参数，极大节省存储并增强鲁棒性。  
   压缩过程见**预处理特征3.2**。

## 六、数据结构与存档系统

1. **ECS分离策略**  
   将世界逻辑拆分为底层自然场（System）与玩家造成的上层偏差（Component）。  
   - System层：存储周期参数、场状态、振荡器状态，按确定性规则独立演化。  
   - Component层：存储玩家的破坏、放置、生物标记等偏差，格式为稀疏集合 \(\{(坐标, 类型, 强度, 时间戳)\}\)。

2. **4KB对齐的区块文件**  
   每个5×5区块的存档设计为4KB的整数倍，便于直接映射到IO管线，降低读写开销。文件结构包含：  
   - 区块头（全局时间戳、周期参数、负反馈系数）  
   - 底层场数据（温度、以太浓度等连续场离散值，量化为16位精度）  
   - 上层偏差（稀疏存储的玩家修改，每笔记录16字节）  
   - 智能体休眠状态（种群的简化周期参数）  
   - 标记生物GSFT索引（指向全局表的偏移量）

3. **确定性重放**  
   采用确定性算法与固定时间步长，结合事件日志（玩家操作序列），可完整回溯世界任意时刻的状态，支持分支与调试。  
   重放命令格式：`/replay <timestamp> [branch]`，将世界回退至指定时间点的确定性状态。

## 七、性能边界与硬件适配

> 本节为关键工程声明，直接约束设计决策。

### 7.1 为何采用2²⁰有限递归环面世界？

本项目初始设计曾考虑“真正的无限开放世界”（即坐标可无限增长的I64方案），但在分析以下约束后，决定转向**2²⁰（1,048,576单位周长）的递归环面拓扑**：

1. **标记生物追踪的IO爆炸问题**（见预处理特征3.9）：开放无限世界下，标记生物可能分散在极端坐标，GSFT的查询延迟随坐标跨度增加而线性增长，且跨区块迁移需要处理I32溢出风险。
2. **地形模板的严格一致性要求**：若采用开放世界，首次生成的地形基元必须永久存储（否则无法保证严格一致性），存储量随探索范围线性增长，在长期游玩中必然超过移动端1GB内存限制。
3. **计算着色器的数值稳定性**：FFT和PDE求解器在坐标超过2²³时，单精度浮点数的ULP将超过0.125，导致频谱分析精度显著下降，影响周期压缩/展开的保真度。
4. **玩家实际移动范围**：考虑到移动端操作特性，玩家在2²⁰环面上绕行一周需约 \(10^5\) 秒（以常见移动速度计算），远超单次游戏会话时长。**在玩家体验中，2²⁰的周长已等同于“无限”**。

因此，本项目采用**I32区块索引（±2³¹）× 区块大小65536（2¹⁶）**的层级编码，实际寻址范围为 \(2^{31} \times 2^{16} = 2^{47}\)，但通过**全局取模映射**将所有坐标投影到 \(2^{20}\) 的环面上。取模操作在着色器端进行，其计算开销可忽略。

**总结**：2²⁰并非“退化”，而是在保证玩家“无限感”体验不受损的前提下，对计算可终止性和存储确定性的必要收束。

### 7.2 多端硬件适配基准

| 平台 | 基准配置 | 观测窗尺寸 | 活跃实体上限 | 标记生物GSFT上限 |
|------|---------|-----------|-------------|----------------|
| PC端 | i7 + GTX 1060 | 5×5区块 | 2000~3000 | 65536 |
| 移动端 | 四核 + 8GB RAM | 5×5区块 | 400~600 | 16384 |
| 网页端（若发布） | 1GB缓存 | 3×3区块（降级） | 200~300 | 4096 |

> **说明**：网页端建议采用服务器-客户端架构，将PDE求解和GSFT维护卸载至后端，客户端仅负责渲染与输入转发。

### 7.3 场景活跃单位上限

| 项目 | 推荐值 | 说明 |
|------|--------|------|
| 玩家操控总实体 | ≤ 150 | 核心个体 + 跟随者 + 临时召唤 |
| 单区域环境响应种群 | 20~50 个实体 | 自然生态背景 |
| 单种群组表示 | 20~40 个实体 | 代表数百个体的简化采样 |
| **场景活跃实体硬上限** | **2000~3000** | 超过此数将触发LOD降级或GC |
| 中心区块活跃密度 | 80~120 个/区块 | 主要交互区 |
| 外围区块活跃密度 | 20~50 个/区块 | 生态背景区 |
| 全局逻辑单位池 | 100,000 | 仅存于GSFT和周期参数中，不展开实体 |

## 八、玩法层补充：种群领导与单位规模设计

> 本节补充说明玩家在“有限控制”前提下的具体操作模式。

### 8.1 单位层级与操作预算

基于“任意个体均具备强操作性”的设计前提，玩家随身单位按生态角色分为三层：

| 层级 | 类型 | 常规携带 | 上限 | 功能定位 |
|------|------|----------|------|----------|
| **神祇** | 具名英雄，不绑定单一元素 | 1 | 2 | 决定象性（光/暗）、提供领域增益、极化已有生物 |
| **高阶种群领导者** | 元素代表，领导同属性种群 | 2 | 3 | 号令种群、改造环境、决定元素浓度 |
| **低阶特工** | 探索/培养中的个体 | 1 | 2 | 挑起种群斗争、捡漏、触发性事件 |
| **核心个体合计** | | **4** | **7（极限）** | 玩家实际操作对象 |

该配置符合人类工作记忆7±2组块规律，确保每个核心个体都有被深度操作的机会，同时不影响大世界探索与宏观决策。

### 8.2 子单位与种群规模

子单位由高阶领导者自动带领，不占用玩家操作预算：

| 领导者阶位 | 常规带领 | 极限带领 | 条件 |
|------------|----------|----------|------|
| 初阶领导者 | 6~8 | 10 | 依赖环境元素浓度 |
| 高阶领导者 | 8~16 | 20 | 需已改造的环境领域 |

玩家侧总实体上限建议为 **150 个**（核心个体 + 跟随者 + 临时召唤），超过此数将导致信息过载与操作效率急剧下降。

### 8.3 死亡与复活机制

复活点融入世界环境，不依赖建筑体系：

| 单位类型 | 复活点 | 冷却时间 |
|----------|--------|----------|
| 神祇 | 世界锚点/神龛/领域核心 | 1 个世界日 |
| 种群领导者 | 对应元素浓度最高的区域 | 15~30 分钟 |
| 低阶特工 | 玩家身边/任意安全点 | 5 分钟 |
| 子单位 | 由领导者重新召集 | 取决于元素浓度 |

此设计强化区域控制与生态经营的价值，单位损失不依赖简单回城，而是回到对应元素区域恢复，与创世进程中的负反馈自愈机制形成玩法呼应。

### 8.4 与区块节律的耦合

玩家单位在区块脱离观测后，其种群状态被压缩进区块的周期参数中（如种群密度波动频率、元素浓度偏置）。玩家返回时，种群根据区块当前周期参数重新展开，确保生态一致性。

神祇领域的象性偏置（光/暗浓度）作为区块周期参数的附加分量存储，影响该区块内生物极化方向。高阶领导者留下的环境改造（湖泊、旱地）则作为上层偏差记录，遵循区块负反馈恢复速率逐步自然愈合或固化为新底层场参数，视改造强度与持续时间而定。

## 九、与《我的世界》的核心差异对照

为更清晰地定位本项目的设计定位，特与《我的世界》（Minecraft）做如下对照：

| 维度 | 《我的世界》 | 本项目 |
|------|-------------|--------|
| **地形生成** | 基于噪声函数的预设地形高度图，生成后固定不变 | 从均匀以太场出发，经元素反应动态涌现，持续演化 |
| **区块粒度** | 16×16×256 格点，固定高度 | 5×5格点（平面），高度由元素反应动态决定 |
| **世界拓扑** | 开放平面，边界为虚空或不可达 | 2²⁰单位周长的递归环面，无边界感 |
| **存储策略** | 存储每个方块ID（压缩为NBT） | 存储周期参数 + 上层偏差 + 频谱分量，4KB对齐 |
| **标记生物** | 独立实体存储于区块文件，跨区块需加载整个区块 | 全局签名频率表（GSFT），跨区块仅需更新表记录 |
| **玩家控制力** | 直接放置/破坏方块 | 放置元素源，通过负反馈回路间接影响地形演化 |
| **世界恢复** | 不恢复，玩家改动永久固定 | 负反馈驱动偏差逐步衰减，长期扰动可固化为新参数 |
| **无限性** | 坐标轴无限延伸（受限于32位），但缺乏感知深度 | 数学闭合（2²⁰），但通过谐波叠加提供感知上的无限独特性 |

## 十、核心创新与理论贡献总结

1. **将区块建模为非线性振荡器**，使地形、气候、生态不再是被动“存储”的数据，而是主动“振动的节律”——这是对传统程序化生成范式的根本性替代。

2. **引入谱方法进行状态压缩与周期折叠**，将智能体的复杂行为压缩为少数频率分量，使“无限世界”的存储开销收敛到 \(O(1)\) 量级，直接解决了开放世界游戏的存档膨胀问题。

3. **用负反馈控制替代传统的事件脚本系统**，使世界的“自愈性”和“玩家影响力”得以在同一数学框架下统一描述，消除了脚本驱动的僵硬感和不可预测性。

4. **提出全局签名频率表（GSFT）作为标记生物追踪的工程方案**，在 \(O(1)\) 的恒定代价下实现了跨区块生物追踪，回避了传统方案中“加载整个区块才能访问实体”的IO瓶颈。

5. **明确论证了2²⁰递归环面的必要性**：在移动端硬件约束下，这是唯一能在保证“无限感”体验的同时，确保计算可终止性和存储确定性的闭合方案。

6. **构建了“玩家有限控制”与“世界无限响应”之间的桥梁**：通过谐波叠加机制，玩家的每一个有限操作（最多6个焦点对象）都会在世界频谱中留下永久可追溯的印记，使得“有限”的操作在“无限”的时间尺度上持续回响。

---

> **最终陈述**：本项目并非试图在物理层面模拟一个“无限大”的宇宙——这是计算资源所不允许的。它试图构建的，是一个**在感知层面呈现无限深度、在数学层面具有严格闭合性的递归世界**。它的“无限”不体现在坐标轴的延伸长度上，而体现在：**玩家每一次有限的选择，都会在世界频谱中产生永不消逝的新谐波，使同一片土地在反复到访时呈现出永不重复的细节与面貌。** 这种“无限”，是信息论意义上的，而非几何学意义上的。它更珍贵，也更可实现。
